# Mahuva CRM — Simple Demo CRM for Onion Dehydration Plants

Plan written 2026-11-06 from the two research reports in `docs/research/`.
Status: **APPROVED 2026-11-12.** Decisions: scope as below; database = free hosted Supabase project for the demo (user will provide credentials); language = English + Gujarati toggle for menu, status words, buttons, KPI names, role names and field labels.

## What we are building (demo scope)

One flow, told in plain words, usable on a phone by a plant owner, munim, sales person and plant supervisor:

Inquiry -> Buyer -> Sample -> Quote (WhatsApp share) -> Order (PI) -> Packing (supervisor buttons) -> Dispatch (truck or container + document checklist) -> Money received / Baaki (outstanding) -> Today's follow-ups on Home.

Menu shown in demo (bottom bar on phone: Home, Inquiries, Quotes, Orders, Money; "More" holds the rest):

| Module key | Menu label | Screens |
|---|---|---|
| dashboard | Home | 4 big tiles (New inquiries, Quotes waiting, Orders in production, Money due) + "To do today" list + 3 big buttons |
| leads | Inquiries | list with status chips, detail, new form (6 fields) |
| buyers | Buyers | list, detail (last orders, money due, Call/WhatsApp), new form (name + phone first) |
| samples | Samples | list, send-sample form, 3 status buttons |
| quotes | Quotes | list, detail with floor-price guard, print view, WhatsApp share, "Buyer accepted" -> Order |
| orders | Orders | list, detail with status stepper + supervisor packing card, dispatch form (truck / container), export checklist, print PI / invoice |
| payments | Money | money due list (red/amber/green), money received form (3 taps) |
| catalog | Products | read-only list; cost column only for owner/accountant |
| users | Staff | existing screen, plain copy, 4 big job buttons |
| settings | My Company | existing screen, 2 cards + "More (export)" |
| documents / reports / audit | hidden | papers live inside Quote/Order; Home numbers are the report; history stays in DB |

Not in demo (parked): kanban pipeline, accounting/GL, production/MRP, charts, custom fields, email, LC compliance, FX feeds.

## Security findings to fix in Sprint A (verified by SQL as demo users)
1. CRITICAL: any user can UPDATE own `profiles` row to role owner + all modules (policy FOR ALL on profiles). Fix: revoke writes, add fn_set_user_access / fn_set_user_active with checks.
2. CRITICAL: `v_product_costs` view bypasses RLS (no security_invoker); sales sees costs. Fix: `WITH (security_invoker = true)` on every view + CI check.
3. HIGH: `GRANT ALL` gives TRUNCATE to authenticated; any user can wipe any table across tenants. Fix: grant only SELECT/INSERT/UPDATE/DELETE, revoke TRUNCATE.
4. HIGH: audit_log readable by all org members and contains cost rows + bank details. Fix: gate by audit module, redact cost/bank columns.
5. HIGH: table write policies check org only, not module (ops user changed floor prices and wiped bank details via PostgREST). Fix: fn_has_module() in write policies; money/state tables writable only via SECURITY DEFINER functions.
6. MEDIUM: app.current_org / app.override_module_check GUC overrides; fn_next_code/doc_no callable by anyone; auth.uid() overwritten on Supabase; no session refresh middleware.
